# 시설 표시 복원 아레나

2026-10-13. 사용자 요청: CCTV·경찰시설·병원 표시를 지도에 남기고, 왼쪽이나 오른쪽에 표시 제어를 배치하는 방향 검토.

이번 작업은 설계 검토다. 앱 코드는 수정하지 않았다. 현재 모바일 화면과 데이터 구조를 확인하고, 동시 실행 한도에 맞춰 하위 에이전트 3개를 재사용해 8개 전략을 작성했다. 각 새 전략에서는 이전 답을 섞지 않도록 지시했다. 이후 대진별로 양측 관점의 공격, 기준별 심사, 패자 장점 흡수를 진행했다. 점수는 내부 정성 평가이며 실제 사용자 조사나 검증된 사용성 수치가 아니다.

## 과제와 기준

직전 수정의 약점: 지도 조작부와 시설 핀을 함께 숨기면서, 주변 시설을 한눈에 발견하던 장점까지 줄였다.

기준은 발견성 / 지도 시야 / 한 손 조작 / 상태·데이터 정확성 / 기존 디자인 조화. 각 10점, 동일 비중이다. 한 손 조작 점수는 배치에 대한 가설이며 실제 기기 테스트 결과가 아니다.

## 🏆 우승 — 극단간결파, 하단의 기존 공간 활용

**CCTV·경찰·병원과 응급의료기관 핀을 처음부터 함께 보여준다. 기존 ‘주변 시설’ 버튼 자리에 짧은 표시줄을 둔다.**

`[✓ CCTV] [✓ 경찰] [✓ 의료] [목록]`

- 지도 색상과 도로·공원 표현, 상단 위치 선택, 설정·내 위치, 하단 내비게이션과 도움·흔들기는 유지한다.
- 최초 진입 시 세 그룹을 모두 켠다. 이후에는 사용자의 선택을 유지한다. 각각 독립적인 토글이며 CCTV를 꺼도 경찰·의료 핀은 남는다.
- 의료는 일반 병원과 응급의료기관을 포함한다. 일반 병원은 기존 API의 좌표를 지도와 연결한다. 응급기관은 핀 형태·응급 배지와 상세 명칭으로 구분한다. 동일 시설로 확인된 데이터만 한 핀에 여러 속성을 연결한다.
- 켜짐은 배경색뿐 아니라 체크, 글자, 접근성 상태로도 전달한다. 제어 버튼은 약 44~48px의 터치 영역을 설계 목표로 삼는다. 이는 WCAG 최소 기준의 인용이 아니다.
- CCTV는 작은 카메라 표식, 경찰·의료는 구분되는 시설 아이콘을 사용한다. 이름은 선택한 시설에서 우선 보여준다. 겹치는 핀은 종류를 나타내는 숫자 없는 묶음으로 표시하고, 누르면 확대하거나 해당 묶음의 시설 목록을 연다. 지도 핀 위치를 임의로 옮기지 않는다.
- 핀을 누르면 작은 상세 카드가 표시줄 위에 열린다. 표시줄은 같은 위치에 남는다. 전체 모달에서는 뒤쪽 지도 조작을 막고 닫으면 상태와 초점을 복원한다.
- 목록 진입점을 유지한다. 목록에서는 일반 병원·응급의료를 구별해 찾을 수 있다. 목록 검색 필터와 지도 표시 상태는 분리한다. 목록 필터를 바꿨다는 이유만으로 다른 지도 핀을 끄지 않는다. 응급기관만 지도에 표시하는 선택이 필요하면 사용자가 명시적으로 적용하는 의료 세부 설정으로 제공한다.
- 320px에서도 이름과 체크를 유지한다. 글자 확대 때문에 공간이 부족하면 두 줄을 허용한다. 첫 구현 전에 상세 카드·키보드·가로 화면과의 충돌을 확인한다.

왜 이겼나:

1. 시설을 처음부터 보여 사용자 피드백의 핵심을 반영한다.
2. 기존 버튼 공간을 활용해 지도 양옆에 추가 가림을 만들지 않는다.
3. 표시 상태를 보고 바로 조절할 수 있고, 작은 상세 카드가 열려도 조작 위치가 유지된다.

## 옆면 배치를 선택한다면

**오른쪽 세로형을 먼저 시안으로 검토한다.** 상단의 기존 지도 도구와 같은 쪽에 모아 반대편 시야를 남길 수 있기 때문이다. 다만 오른손 사용자에게 더 쉬울 것이라는 추정만으로 확정하지 않는다. 왼손 사용자, 320px, 열린 카드와의 간섭을 실제로 비교해야 한다.

왼쪽 세로형은 시설과 지도 조작을 분리한다는 장점이 있다. 반면 현재 오른쪽 도구를 유지하면 양쪽을 가리고, 76px처럼 넓은 패널은 작은 지도에서 부담이 된다. 좌우 어느 쪽도 별도 큰 목록 패널을 상시 펼치는 형태는 권하지 않는다.

우승안은 좌우 배치가 필수 조건이 아니라는 현재 요청을 기준으로 선정했다. 옆면 배치를 필수 조건으로 정하면 후보 순위는 달라질 수 있다.

## 준우승 — 역발상파

하단에 CCTV·경찰·병원·응급·목록을 모두 독립 버튼으로 두는 안. 응급기관만 바로 선택하는 장점이 있지만 작은 화면에서 다섯 항목과 두 줄이 차지하는 높이가 커진다. 우승안은 이 안의 의료 세부 구분을 목록·세부 설정으로 흡수했다.

## 대진표와 흡수

점수 배열은 발견성 / 시야 / 한 손 / 상태·정확성 / 조화 순서다. 라운드마다 보완된 안을 새로 평가하므로 이전 점수와 합산하지 않는다.

| 경기 | 결과 | 기준별 점수 | 승자가 흡수한 요소 |
| --- | --- | --- | --- |
| 8강 1 | 역발상 39 > 정석 38 | 9/7/8/8/7 : 9/6/6/9/8 | 명시적인 시설 목록 입구 유지 |
| 8강 2 | 스토리 41 > 숫자 38 | 9/8/8/8/8 : 8/9/6/7/8 | 터치 영역·버튼 간격 규격 |
| 8강 3 | 간결 42 > 고객 40 | 9/8/9/8/8 : 8/8/7/9/8 | 숫자 없는 군집 |
| 8강 4 | 실험 41 > 전문가 39 | 8/9/7/9/8 : 9/7/6/9/8 | 카드 개폐에도 표시 제어 위치 고정 |
| 4강 1 | 역발상 42 > 스토리 41 | 8/8/9/8/9 : 9/8/8/8/8 | 충분한 터치 영역과 간격 |
| 4강 2 | 간결 43 > 실험 42 | 9/8/9/8/9 : 8/9/8/9/8 | 동일 의료기관의 확인된 중복만 합침 |
| 결승 | 간결 44 > 역발상 41 | 9/9/9/8/9 : 9/7/8/9/8 | 일반 병원·응급기관의 독립적인 세부 선택 |

각 경기의 상호 공격:

1. 정석→역발상: 토글로 대체하면 목록 입구가 사라진다. 역발상→정석: 넓은 왼쪽 패널은 작은 화면을 가린다.
2. 숫자→스토리: 카드에서 제어 위치가 바뀐다. 스토리→숫자: 카드에서 제어가 숨겨져 비교를 방해한다.
3. 고객→간결: 병원 묶음의 범위가 모호하다. 간결→고객: 카드를 열면 표시 상태 확인이 어려워진다.
4. 전문가→실험: 손잡이가 움직여 조작 위치를 다시 찾아야 한다. 실험→전문가: 상단 네 토글은 높이와 도달 거리 부담이 있다.
5. 역발상→스토리: 카드 전환 중 제어 이동. 스토리→역발상: 항목을 추가하면 하단이 두 줄로 커진다.
6. 간결→실험: 추가 펼침과 카드 충돌 미해결. 실험→간결: 응급기관만 고를 수 없다.
7. 역발상→간결: 의료 구분이 불명확하다. 간결→역발상: 다섯 버튼은 지속적인 지도 가림을 늘린다.

숫자파의 ‘세로 면적이 30% 작다’는 계산은 제안한 두 규격 사이의 산술 비교일 뿐이다. 같은 버튼 조건의 비교가 아니므로 세로 배치 자체의 우월성 근거에서 제외했다. 가짜 사용자 조사나 효과 통계를 근거로 채택하지 않았다.

## 코드에서 확인한 구현 범위

- 현재 `LivePlacesMap.tsx`는 단일 `category`이며 초기값은 null이다. 복수 표시 상태, 목록 필터, 선택 핀을 분리해야 한다.
- `TourSafeMapPanel.tsx`는 실제 좌표별 DOM 마커를 생성한다. 밀집 묶음과 겹친 핀 선택은 추가 작업이다.
- CCTV는 직선 3km 원자료 중 최대 40개를 간격을 두고 지도에 표시한다. 500m 설치지점 집계는 별도다. 묶음 표식을 전체 CCTV 수로 읽히게 만들지 않는다.
- 경찰은 조회 후보 최대 3곳이다. 모든 경찰시설의 수나 분포를 나타내지 않는다.
- 일반 병원 API는 이미 각 병원의 lat/lng를 반환한다. 같은 시군구·5km 내 최대 12개 일부 후보이며 현재 별도 병원 화면에 연결되어 있다. 지도 핀 연결을 추가해야 한다.
- 현재 지도 MEDICAL은 응급의료기관 자료다. 일반 병원과 명칭만 바꿔 섞지 않는다. 같은 이름이나 가까운 좌표만으로 중복을 확정하지 않는다.
- 시설 조회 중·실패·성공했지만 빈 결과를 구별한다. 켜진 토글은 표시 의도이며 자료 조회 성공을 의미하지 않는다. 등록 시설과 시간표는 현재 작동·진료·수용 가능 여부나 안전 보장이 아니다.

## 확인한 접근성 참고

- [W3C: Target Size Minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html): 최소 목표 크기·간격과 예외를 설명한다. 이번 44~48px는 프로젝트의 설계 목표이며 WCAG AA 최소가 44px라는 뜻이 아니다. 작은 지도 핀을 선택하기 어려운 사용자를 위해 목록도 남긴다.
- [W3C: Use of Color](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html): 켜짐·종류를 색만으로 전달하지 않고 체크·아이콘·글자를 함께 제공하는 판단에 참고했다.

다음 구현 전 확인할 화면: 320×740, 390×844, 큰 글자, 가로 화면, 시설 카드가 열린 상태, 자료 실패 상태. 사용자 조작성 비교는 아직 수행하지 않았다.
