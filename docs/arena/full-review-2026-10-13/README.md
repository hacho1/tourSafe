## 우승안 — 극단간결파 + 충돌 자료 관리

결승은 극단간결파 46/50, 숫자파 45/50으로 근소한 차이였다. 정성 점수이며 실측 제품 점수가 아니다. 우승안은 초록색 지도를 유지하면서 **지도 실패에도 도움을 남기기 → 확인된 충돌 자료 구분 → 지도·여행지 위치와 분류 필터 연결 → GPS 실패·날씨 지연 복구** 순서로 수정한다. 숫자파의 시설 ID·원본 버전·출처를 묶은 충돌 관리 하나를 흡수했다.

이긴 이유는 실제로 관찰된 실패를 작은 변경과 검증 조건으로 연결하고, 기능을 더 늘리지 않고도 다음 행동을 명확히 만들며, 전국 자료의 오류를 추측으로 덮어쓰지 않기 때문이다. 준우승 숫자파는 자료 갱신·검색 범위·병원 부분 실패를 먼저 깊게 다루는 대안이다. 이후 전국 자료를 운영하는 단계에서 강점이 있다.

별도 확정 UI 보정 항목인 조회 위치 점 가림, 저장 목록의 독립 접근, 병원 상세 실패 복구도 아래 점검 목록에 남겼다. 토너먼트의 승패가 확인된 결함을 기각하는 뜻은 아니다. [결승과 최종 완성안](tournament-final.md).

## 검토 방식

정석·역발상·숫자·스토리·고객시점·극단간결·전문가·실험의 8개 전략 답안을 만들었다. 동시 실행 한도에 맞춰 하위 에이전트 3개를 재사용했고, 새 전략에서는 이전 답을 섞지 않도록 지시했다. 첫 라운드는 서로의 답을 보지 않고 코드·자료를 읽었다. 이후 8강 4경기→4강 2경기→결승에서 서로의 약점, 5개 기준 점수, 패자에게서 흡수할 요소 하나를 기록한다. 점수는 답안에 대한 정성 평가이며 제품의 실제 사용자 성공률이 아니다.

심사 기준: 급한 도움 발견성 / 모바일 가독성·조작성 / 데이터·위치 정직성 / 오류·권한·빈 결과 복구 / 재현 근거·실행 가능성.

## 먼저 고칠 문제

### 1. P1 — 좌표 변환 성공과 시설 위치 확인을 구분해야 한다

제공된 화장실 CSV의 `명목보건진료소`는 안성시 중앙로 308로 기록되어 있고 지도는 이를 직선 210m의 시설로 안내한다. [안성시 보건소](https://www.anseong.go.kr/health/contents.do?mId=0103020000)와 [경기도 공중화장실 안내](https://water.gg.go.kr/main/ctzn/restroom.do?pageIndex=809)는 양성면 속말길 10으로 안내한다. 경기도 안내의 등록 개방시간도 앱 자료와 다르다. 원본 CSV 물리행 21874, 파일 해시, 적재 이름/주소를 대조했으므로 확인한 사례는 CSV 열을 잘못 읽은 문제가 아니다. 실제 이전·오기 원인과 현장 상태는 미확인이다.

**최소 수정:** 확인된 충돌은 원본 버전·시설 ID·확인 출처를 기록해 재검증 전 지도 길찾기에서 격리한다. 원본 값은 보존한다. 전체를 다시 주소 변환하는 것으로 해결되지 않는다. 46,945건은 주소 좌표 연결 성공 수이며 시설 동일성 검증 완료 수가 아니다.

근거: `backend/src/utils/toiletGeocoding.ts:53`, `frontend/src/components/LivePlacesMap.tsx:138`. [화면](toilet-address-mismatch.jpg), [수치·원본 대조](round1-numbers.md).

### 2. P1 — 지도 파일 다운로드 실패가 도움 화면까지 없앤다

별도 탭에서 지도 모듈 요청만 차단하자 전체 앱이 백지가 되고 도움 버튼도 사라졌다. `Failed to fetch dynamically imported module` 오류를 확인했다. 기존 지도 타일 오류 처리나 시설 API 오류 처리와 다른 실패다. 테스트 후 차단·캐시 설정을 복원하고 임시 탭을 닫았다.

**최소 수정:** 지도 전용 오류 경계를 두고 실패해도 앱 메뉴·주변 목록·도움 연락처는 남긴다. 모듈 재시도 또는 재연결 동작을 제공한다.

근거: `frontend/src/components/LivePlacesMap.tsx:16`, `:122`, `frontend/src/components/MapPanel.tsx:6`, `:109`. [실패 화면](map-module-failure.jpg), [브라우저 재현](browser-evidence.md).

### 3. P2 — 병원 시간표 실패가 이미 확보한 연락처까지 버린다

기본 목록은 정상이어도 모든 상세 요청이 실패하면 서비스가 예외를 던지고 병원 카드 전체가 사라진다. 일부 실패에서는 기본 카드가 남으므로 100% 상세 실패 때만 유용한 정보가 더 많이 사라지는 구조다. 기존 테스트도 이 예외를 기대한다. 실제 기관 장애를 유발한 검증은 아니다.

**최소 수정:** 목록 성공/상세 실패를 나누고 이름·주소·전화는 유지하며 진료과·시간표만 미확인으로 표시한다. 빈 결과에서 위치 변경을 직접 제공한다. 지도 카드의 현재 접수·수용 미확인 문구도 전화/길찾기 앞에 둔다.

근거: `backend/src/services/hospitals.ts:70`, `tests/hospitals.test.ts:182`, `frontend/src/components/LivePlacesMap.tsx:142`. [동선 검토](round1-story.md).

### 4. P2 — 지도·여행지·저장 화면이 하나의 여행 흐름으로 이어지지 않는다

지도에서 한경국립대학교 안성캠퍼스를 보고 여행지를 열면 서울 성수 결과가 나온다. 양쪽 위치는 별도 상태다. 저장은 ID만 남기고 현재 추천 결과와의 교집합만 보여 주므로 다른 지역 검색·재접속 뒤 저장 장소를 직접 다시 열기 어렵다. 저장 기록이 삭제되는 문제와는 다르다.

**최소 수정:** 지도에서 여행지로 넘어갈 때 조회 위치를 공유하거나 명시적인 `이 위치로 찾기`를 제공한다. 저장 목록에는 최소 장소 스냅샷을 남겨 현재 추천 검색과 독립적으로 이름·주소·삭제·재열기를 제공한다. 긴급 전달용 GPS는 실제 기기에서 새로 확인하는 정책을 유지한다.

근거: `frontend/src/pages/SafetyMap.tsx:15`, `frontend/src/ExploreApp.tsx:42`, `:68`, `frontend/src/utils/savedPlaces.ts:10`. [위치 전환 화면](explore-mobile.jpg), [정석파 검토](round1-classic.md).

### 5. P2 — 숫자 군집이 도움 종류와 조회 위치를 가린다

안성에서 `표시된 시설 모두 보기`를 누르면 CCTV·경찰·의료·화장실을 포함한 61개가 숫자 하나로 보인다. 실제 20×20px 조회 위치 점과 겹쳐 점이 가려졌다. 이전 시설 마커끼리 겹침 0건 검증에는 조회 위치 점이 포함되지 않았다. 숫자가 시설을 모두 세거나 안전성을 뜻하는 것은 아니라는 안내는 유지해야 한다.

**최소 수정:** 조회 위치 점을 가리지 않도록 군집 배치/우선순위를 보정한다. 경찰·의료 등 도움 종류를 고르면 해당 종류의 가까운 후보를 바로 볼 수 있게 한다. 시설을 다시 여러 아이콘이 든 큰 상자로 겹치는 방식으로 되돌리지 않는다. 토글은 `지도에 표시`, 목록은 `주변 목록`으로 뜻을 드러내는 안을 검토한다.

근거: `frontend/src/components/TourSafeMapPanel.tsx:115`, `:130`, `:160`, `frontend/src/utils/mapLayers.ts:53`. [실제 가림 화면](map-cluster-overview.jpg), [UI 검토](round1-customer.md).

### 6. P2 — 데이터가 없는 실내·야외 필터가 정상 결과를 모두 숨긴다

LIVE 성수 결과 8곳에서 야외·실내 필터가 각각 0곳이 되는 것을 재현했다. 원본 정규화 값은 모두 `null`인데 필터는 true/false만 허용한다. 미확인 분류 안내는 있으나 다른 지역이나 반경을 권유해도 분류 데이터가 생기지 않는다.

**최소 수정:** 분류 가능한 자료가 없을 때 필터를 비활성화하거나 숨기고 미제공 상태를 설명한다. 장소명으로 실내·야외를 추정하지 않는다.

근거: `backend/src/adapters/tourApi.ts:138`, `frontend/src/ExploreApp.tsx:69`. [실제 빈 결과](explore-outdoor-empty.jpg), [간결파 검토](round1-minimal.md).

## 유지할 강점과 검증 범위

초록색 지도는 투어세이프의 시각적 정체성으로 유지할 가치가 있다. 실제 도로와 종류별 단일 아이콘, 같은 좌표의 개별 선택 목록, 주소 좌표/직선거리/미확인 정보 표기는 유용하다. 도움 연락처는 위치 확인을 기다리지 않고 접근할 수 있다. 시설 조회 통신 실패를 정상 0건이나 예시 자료로 바꾸지 않는 점도 유지한다.

이번 실행에서 `npm test` **127개 통과**, TypeScript/Vite 빌드 통과. 의도적인 오프라인→오류 안내→도움 접근→네트워크 복원→재조회 복구를 확인했다. 일반 조작의 JavaScript 오류는 관측하지 않았다. 지도 모듈 차단 실험은 별도 백지 화면 오류를 재현했다. 화면 크기·차단·네트워크 설정은 복원했고 임시 탭은 닫았다.

실제 통화 연결, 신고 접수, 현장 개방 상태, 실제 기기 GPS·흔들기, 저사양 휴대폰 성능, 운영 배포는 이번 검증 범위에 포함하지 않는다. 이번 점검에는 기능 수정·배포가 없다.
