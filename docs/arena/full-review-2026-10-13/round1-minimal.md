# 아레나 6/8 — 극단간결파

**초록 지도는 그대로 두고, ‘도움 → 위치 → 필요한 장소’만 명확하게 만든다.** 이번 독립 점검은 코드 읽기만 했다. 브라우저·테스트·API 호출·앱 수정은 하지 않았으며, 아래 재현은 부모가 확인할 절차다.

| P1 | 지도와 여행지가 별도 조회 위치를 가진다. `frontend/src/pages/SafetyMap.tsx:15`의 location은 `frontend/src/App.tsx:68`~`:71`에서 여행지로 전달되지 않는다. `frontend/src/ExploreApp.tsx:42`~`:49`는 자체 기본 위치로 시작한다. | 지도에서 제주를 선택한 뒤 처음 ‘여행지’를 연다. 여행지는 자체 기본 위치로 검색한다. 지도 목록의 ‘여행지 조건으로 검색’도 위치 없이 이동한다(`frontend/src/components/LivePlacesMap.tsx:174`). 사용자는 방금 보던 지역에서 여행지를 고른다고 기대할 수 있다. 화면에서 실제 기대 혼동의 정도는 미관측이다. | 지도·여행지의 조회 위치를 App에서 공유하고 이동 직후 지역명을 보여준다. 여행지에서 다른 지역을 고르는 것은 명시적 변경으로 남긴다. 응급 도움의 GPS는 기존처럼 새로 확인한다. |

## 꼭 남길 행동 3가지

1. **도움 열기 → 연락할 곳 선택.** 하단 도움 버튼(`MobileNav.tsx:12`)과 위치 확인 없이 전화 앱을 여는 선택지(`EmergencyHelp.tsx:85`~`:93`)를 유지한다. 실제 통화·신고 완료처럼 표시하지 않는다.
2. **조회 위치 한 번 정하기 → 주변 시설·여행지로 이어가기.** 지도·여행지에서 같은 지역을 보고, GPS 실패에는 검색·주소 입력으로 바로 복구한다. 선택한 여행지를 실제 내 위치로 취급하지 않는다.
3. **장소 선택 → 길찾기 또는 저장.** 장소명·직선거리·자료 상태·저장 상태를 먼저 보여준다. 흔들기는 선택 설정으로 유지하고 기존 도움 화면만 연다(`EmergencyHelp.tsx:116`). 센서 실패 때 도움 버튼으로 안내하는 현재 처리도 유지한다(`useShake.ts:17`~`:19`).

## 없애거나 접을 것 3가지

1. **작동하지 않는 실내·야외 필터를 없앤다.** 분류 자료가 생긴 뒤 다시 노출한다.
2. **화면마다 별도로 시작하는 위치 설정을 없앤다.** 공통 조회 위치와 명시적인 ‘위치 바꾸기’만 둔다. 응급 도움의 새 GPS 확인은 유지한다.
3. **실패 후 수동 주소 입력의 추가 접힘을 없앤다.** 주소 입력은 바로 열고, 신고 요령·출처·흔들기 설정 같은 읽을거리는 현재처럼 접어둔다.

**완성 화면 원칙:** 지도 첫 화면은 조회 지역, 필요한 시설, 도움 버튼에 집중한다. 장소를 누르면 이름·거리·확인 상태와 행동 버튼을 보여준다. 도움은 연락 선택이 먼저다. 저장·여행지로 이동해도 방금 선택한 지역을 잃지 않는다. 모바일 체감·실기 흔들기 성공률은 코드만으로 통과 판정하지 않는다.
