녹색 커스텀 지도와 현재 흐름을 유지하되, 먼저 **잘못된 원본 명칭·주소가 정확한 좌표처럼 길찾기로 이어지는 문제**를 해결해야 한다. 주소 문자열의 일치율과 테스트 통과만으로 실제 시설의 위치 정확도를 보증할 수 없다.

## 1. [P1] 원본 명칭·주소 충돌이 실제 시설 길찾기에 전파된다

**확인 사실.** 부모가 관측한 한경국립대학교 안성캠퍼스 조회 요청은 `lat=37.01185387050689&lng=127.26377015168558&area=`이다. 이 좌표로 로컬 `getPublicFacilities`를 호출하면 아래 세 거리가 화면과 정확히 일치한다. 위경도 뒤바뀜이나 haversine 계산 오류가 아니다.

| 원본 CSV 물리행 | 화장실명 | 원본 도로명주소 | 화면/재계산 거리 |
|---|---|---|---:|
| 21837 | 갤러리IC주유소 | 경기도 안성시 안성맞춤대로 1150 (금산동, 안성시립중앙도서관) | 575m |
| 21874 | 명목보건진료소 | 경기도 안성시 중앙로 308(석정동) | 210m |
| 21903 | 죽산농협주유소 | 경기도 안성시 남파로 73-3 | 719m |

원본은 `C:/Users/ses18/Downloads/공중화장실정보.csv`이며 SHA-256이 현 manifest와 일치한다. 헤더 34개가 모두 유일하고, 위 3행의 명칭·주소가 적재 자료와 일치한다. 따라서 확인한 사례는 importer가 열을 잘못 맞춘 결과가 아니다.

반면 [안성시 보건소 공식 보건진료소 안내](https://www.anseong.go.kr/health/contents.do?mId=0103020000)는 명목보건진료소 주소를 **양성면 속말길 10**으로 안내한다. 현재 앱 자료의 중앙로 308과 충돌한다. 갤러리IC주유소의 원주소가 도서관을 명시하는 점도 의심스럽지만, 해당 주유소의 공식 현재 주소는 별도로 확정하지 않았다. 충돌의 원인이 오기·이전·다른 시설명인지까지는 단정하지 않는다.

**코드 근거.** `backend/src/utils/publicCsv.ts:13`과 `:27`은 원본 명칭·주소를 그대로 유지한다. `backend/src/utils/toiletGeocoding.ts:53`~`:65`는 주소 자체의 정확일치만 검사하며 시설 동일성은 검사하지 않는다. `frontend/src/components/LivePlacesMap.tsx:138`~`:145`는 해당 이름·거리·좌표를 길찾기로 연결한다.

**영향·최소 수정.** ‘실제 입구와 다를 수 있음’은 시설명과 주소가 다른 문제를 충분히 설명하지 못한다. 확인된 충돌 ID를 원본 버전과 함께 품질 예외 목록에 기록하고, 재검증 전 지도 길찾기 대상에서 제외하거나 ‘자료 간 주소 불일치’ 상태로 분리한다. 원 CSV와 원본 값은 보존한다. 전체 자료를 새로 지오코딩해도 원본 주소가 같으면 같은 오류가 반복된다.

**검증 맹점.** 기존 주소 일치 테스트는 잘못된 이름에 붙은 주소를 정확히 변환한 경우를 정상으로 통과시킨다. 원본→적재→좌표→공식 시설 동일성의 소량 표본 대조가 필요하다.

## 2. [P2] 좌표 없는 6,639건 중 적어도 1,281건은 지역 주소 목록에서도 접근하기 어렵다

**확인 사실.** 전국 JSON 전체에 `hasProvince(address)`를 적용하면 1,281건이 false이며 모두 좌표가 없다. 전국 게시 함수는 이 주소의 처음 두 토큰을 지역 키로 저장한다. 조회 함수는 정상적인 시·군·구 키와 주소 접두어가 일치하는 행만 반환한다. 시·도가 생략되거나 붙어 쓰인 행은 정상 지역 검색에서 찾아낼 수 없다. ‘위치 미확인 자료는 지역 주소 목록에 남긴다’는 설명과 실제 접근성이 다르다.

**근거.** `scripts/geocode-toilets-national.ts:34`, `:65`~`:67`; `backend/src/utils/toiletGeocoding.ts:44`~`:49`; `backend/src/adapters/publicFacilities.ts:52`~`:54`. `README.md:289`는 6,639건을 해당 지역 목록에서 제공한다고 설명한다.

**재현.** 전국 좌표 버전의 `tiles`와 `addresses`를 합쳐 행수·`hasProvince`만 집계한다. 정상 지역 조회는 `getPublicFacilities(center,3000,area)`로 확인한다. 또 제주시청 기준 `(33.4996,126.5312)`에서는 주소 목록 총 111건 중 30건만 반환되며, UI에는 페이지 이동이나 나머지 81건 검색 수단이 없다(`publicFacilities.ts:77`, `LivePlacesMap.tsx:177`).

**영향·최소 수정.** 좌표 누락의 보완 경로에서도 자료가 누락된다. 주소 문자열과 별개로 확인된 제공기관·행정구역 메타데이터를 보존하여 검색 키로 사용하고, 확정할 수 없는 행은 ‘지역 분류 미확인’ 검색 대상으로 남긴다. 시·군·구를 추정해 좌표를 만들지 않는다. 지역 목록은 30건 이후 페이지를 제공한다.

**검증 맹점.** `tests/map-layers.test.ts:51`~`:80`은 입력으로 받은 점 보존과 확대 조건을 검사한다. 서버에서 사라진 점의 재발견·상한 소진은 검사하지 않는다.

## 4. [P1] 병원 상세가 모두 실패하면 이미 받은 병원 이름·전화·좌표도 사라진다

**확인 사실.** 목록에서 유효한 병원 최대 12개를 확보한 뒤 4개씩 상세를 조회한다. 일부 실패에서는 해당 병원의 목록 정보를 유지하지만, 12개가 모두 실패하면 `ALL_HOSPITAL_DETAILS_FAILED`를 던진다. 따라서 진료시간 제공자의 장애가 병원 위치·전화 검색의 완전한 실패로 확대된다.

**근거.** `backend/src/services/hospitals.ts:51`~`:71`; 목록에 전화·주소·좌표가 이미 존재하는 `backend/src/adapters/hospitalApi.ts:63`~`:72`; 502로 변환하는 `backend/src/routes/api.ts:44`~`:45`; 실패 시 화면 데이터를 null로 바꾸는 `frontend/src/hooks/useMapHospitals.ts:17`~`:18`.

**재현 조건.** 병원 목록 응답을 정상으로 두고 상세 응답만 전부 실패시키면 된다. 이번 검토에서는 네트워크 장애 주입이나 테스트 실행을 하지 않았다. 기존 `tests/hospitals.test.ts:182`~`:187`가 바로 이 전면 실패를 성공 조건으로 단언하므로 테스트 통과로 사용자 복구성이 입증되지 않는다.

**영향·최소 수정.** 급하게 병원에 전화하려는 사람에게 확보된 후보까지 숨겨진다. 목록 성공·상세 전부 실패를 구분하여 병원 후보는 반환하고 진료과·시간은 미확인으로 표시한다. 목록 자체 실패는 현재 실패 안내를 유지한다.

## 5. [P2] 지역 시설을 읽어도 날씨 두 요청이 끝날 때까지 지도에 제공하지 않는다

**확인 사실.** 지도 요청은 로컬 시설·응급의료·경찰·날씨를 하나의 `Promise.all`로 기다린다. 날씨는 관측 후 예보를 순차 요청하며, 개별 외부 요청의 제한은 9초다. 관측이 9초에 가까운 시간에 성공하고 예보가 시간 초과되면 날씨 하나 때문에 시설 응답도 약 18초 가까이 지연될 수 있다. 실제 지연 측정치가 아니라 코드 경로상 가능한 대기시간이다.

**근거.** `backend/src/services/mapFacilities.ts:14`~`:22`; `backend/src/adapters/weatherApi.ts:35`~`:43`, `:80`~`:88`; `backend/src/utils/http.ts:36`; 새 조회마다 기존 시설을 지우는 `frontend/src/hooks/useMapFacilities.ts:12`~`:17`. 또한 `mapFacilities.ts:16`은 좌표 기반 로컬 자료를 읽기 전에 주소 목록에 필요한 역지오코딩을 먼저 기다린다.

**재현 조건·영향.** 캐시가 없는 위치에서 날씨 응답만 느리게 하면 CCTV·화장실 같은 로컬 자료가 있어도 로딩 상태가 이어진다. 사용자는 도움 시설이 느린지 날씨가 느린지 구분할 수 없다.

**최소 수정.** 날씨를 별도 비동기 조회로 분리하고, 좌표 시설을 먼저 반환한다. 행정구역 주소 목록은 후속 조회로 붙인다. 같은 위치 재조회 중 기존 데이터 유지 시에는 기존 조회임을 표시하고 위치가 달라지면 이전 점은 제거한다.

## 실행 제안

1. 우선순위는 공식 출처와 충돌한 시설의 길찾기 격리 → 상세 장애에도 병원 전화 후보 유지 → 좌표 없는 자료의 검색 경로 복구다. UI 문구만 늘리거나 전국 주소 변환을 재실행해도 첫 문제는 해결되지 않는다.
2. 기존 함수 테스트와 별도로 소량의 데이터 검증 기준을 둔다. 원본 명칭·주소를 공식 기관과 대조한 표본, 전체행/좌표행/지역분류불가/실제표시행의 집계, 동일 주소 다중 화장실이 표시 상한을 소진하는 사례를 포함한다. 전국 API 재호출 없이 현재 파일만으로 대부분 확인할 수 있다.

현재 녹색 지도, 주소 기준 좌표라는 안내, 실제 입구 미확인 표시, CCTV 작동 미확인 안내, ID 기준 병원 병합은 유지할 가치가 있다. 부모가 우려한 ‘모든 시설 보기’의 넓은 지도 범위는 활성 병원 후보가 5km 범위이고 `TourSafeMapPanel.tsx:87`~`:92`가 모든 점의 bounds를 맞추므로 그 자체만으로 거리 오류를 뜻하지 않는다.
