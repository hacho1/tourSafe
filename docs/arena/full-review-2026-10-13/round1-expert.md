# 1라운드 · 전문가파 — 데이터의 상태와 사용자가 받는 결론이 일치하는가

점검 대상은 2026-10-13 `D:/tourSafe`의 데이터 계약, 시간 의존 값, 부분 실패 처리다. 초록색 커스텀 지도는 유지한다. 다른 전략 보고서를 열람하지 않고 관련 소스를 직접 읽었다. 현재 스키마에 있는 필드만 사용했으며, 아래 1번의 점수 계산만 순수 함수에 합성 입력을 넣어 실행했다. 2·3번은 소스에서 도출한 재현 조건이며 브라우저·실제 API·파일 장애 실험을 실행한 결과가 아니다. 실제 키를 열거나 출력하지 않았다.

## 1. P2 · 의료 정보 실패가 추천 점수와 등급을 올릴 수 있다

**확인한 계약:** `calculateScore`는 시설 후보가 없으면 해당 항목의 알려진 배점을 0으로 만들고, 총점은 획득 점수 ÷ 알려진 배점으로 정규화한다. 의료 조회의 실패 fallback도 빈 배열이므로, 멀리 있는 의료시설 정보가 실패하면 낮은 접근성 점수와 그 배점이 함께 제거된다. 추천 정렬은 확인율 60% 미만 여부를 우선 구분한 뒤 총점을 비교하므로, 확인율이 60% 이상이면 정보 누락으로 올라간 점수가 정렬 우선권을 얻는다.

**근거:** `backend/src/utils/scoring.ts:56`, `:63`, `:65`, `:124`, `:126`, `:142`; `backend/src/services/recommendations.ts:101`, `:106`, `:140`; `shared/order.ts:8`, `:9`; `frontend/src/config/constants.ts:17`.

**실행 재현:** 순수 함수 `calculateScore`와 `recommendationOrder`에 다음 합성 조건을 넣었다. 관광지 운영 정보는 확인됨, 날씨는 계산상 적합한 값, 경찰·관광안내소는 각 100m, 의료시설은 4,000m, 가족 편의 항목은 실제 LIVE 정규화 경로처럼 모두 미확인이다. 다른 값은 그대로 두고 의료시설만 제거했다.

| 합성 입력 | 점수 | 확인율 | 등급 |
|---|---:|---:|---|
| 의료시설 4,000m 정보 있음 | 82 | 90% | RECOMMENDED |
| 의료시설 정보 누락 | 100 | 70% | PRIORITY |

동일한 장소 값으로 `recommendationOrder(누락된 결과, 정보가 있는 결과) < 0`도 `true`였다. 특정 실제 관광지가 이 점수를 받았다는 주장은 아니다. 처음에는 가족 정보도 확인된 표본으로 동일 현상을 확인했고, 표의 최종 표본은 LIVE 경로에 맞춰 가족 정보를 미확인으로 다시 검증했다.

**영향:** 조회 실패가 추천을 더 강하게 보이게 한다. 확인율을 함께 표시하는 것은 도움이 되지만, `추천 우선`과 100점은 여전히 더 긍정적인 결론이다. 현재 점수식 자체가 틀린 산술이라는 뜻이 아니라, 서비스 실패와 추천 등급의 관계가 불안정하다는 문제다.

**최소 개선:** 어댑터 오류 상태를 등급/정렬에 전달해 자료 장애가 있는 결과를 정상 조회 결과보다 더 강하게 추천하지 않는다. 미확인 데이터를 “시설 없음”으로 0점 처리하지 말고 `일부 자료 미확인`이라는 별도 결론으로 둔다. 점수 비교를 유지하려면 비교 항목 집합 또는 정보 가용성 정책을 먼저 고정한다.

**완료 기준:** 동일 장소·동일 정상 데이터에서 의료 어댑터를 성공→실패로 바꿔도 추천 등급과 순위가 상향되지 않는다. 미확인은 시설 부재로 표현되지 않아야 한다.

## 2. P2 · 전국 화장실 보강 자료의 장애가 정상 조회와 구분되지 않는다

**확인한 계약:** 전국 화장실 manifest의 `schemaVersion`, `sourceVersion`, 버전 형식 등이 맞지 않으면 `nationalToilets`는 `null`을 반환한다. 파일 읽기 오류는 상위 `getPublicFacilities`에서 catch한 뒤 기존 좌표·주소 목록 경로로 fallback한다. 이 fallback은 CCTV를 계속 보여 주는 데는 유용하지만, 반환값에 전국 보강 자료가 빠졌다는 상태가 없다. 호출자가 예외 없이 반환받으면 `safeAdapter`는 공공시설 전체를 `OK`로 표시한다. 프런트의 화장실 장애 판단도 이 공통 `publicFiles` 상태를 사용한다.

**근거:** `backend/src/adapters/publicFacilities.ts:40`, `:41`, `:73`, `:79`, `:89`, `:93`; `backend/src/services/mapFacilities.ts:15`, `:37`; `backend/src/services/recommendations.ts:40`, `:43`; `frontend/src/components/LivePlacesMap.tsx:106`, `:111`. 기존 `tests/toilet-geocoding.test.ts:115`는 sourceVersion 불일치 뒤 전국 좌표가 제외되는 상황을 실제 테스트 계약으로 담고 있지만 이번 점검에서는 해당 테스트를 실행하지 않았다.

**재현 절차(미실행):** 운영 파일을 수정하지 말고 테스트 전용 루트에 정상 원자료 manifest와 이전 sourceVersion의 전국 화장실 manifest를 둔다 → `getPublicFacilities`를 호출한다 → 화장실 보강 좌표가 제외되면서도 함수는 성공 반환하는지 확인한다 → 응답의 공공시설 상태가 OK가 되어 화장실 재조회 오류 안내가 나오지 않는지 검증한다. 파일 누락·손상도 같은 catch 경로의 조건이다.

**영향:** 전국 위치 자료가 일시적으로 사라져도 사용자는 “정상 조회했는데 표시할 시설이 적음/없음”으로 읽게 된다. 데이터 추가가 크게 줄어든 순간을 API·화면에서 식별할 수 없다. 현재 운영 자료가 실제로 손상됐다는 주장은 아니다.

**최소 개선:** 반환 계약에 원자료와 전국 화장실 보강 자료의 상태를 분리한다. CCTV와 관광안내소는 계속 보여 주고 화장실에는 `전국 주소 위치 자료를 읽지 못해 일부 자료만 표시`를 알린다. 위치 미확인 주소 목록도 범위와 출처를 유지한다.

**완료 기준:** 보강 manifest 누락·버전 불일치·타일 읽기 실패 각각에서 다른 정상 시설은 유지되고 화장실만 degraded/error 상태를 노출한다. 단순한 정상 0건과 자료 장애로 인한 0건은 API와 UI 양쪽에서 구분되어야 한다.

## 3. P2 · ‘현재 운영시간’ 판단에 유효기간이 없다

**확인한 계약:** 관광지 `openNow`는 서버가 관광지 응답을 만드는 시각에 `parseOpenNow`로 계산한다. 프런트의 추천 훅은 좌표·반경·아이 동반 옵션·수동 재조회 값이 바뀔 때만 다시 가져오고, 시간 경과나 창 복귀로는 재조회하지 않는다. 카드 문구는 저장된 boolean을 계속 읽어 `운영시간 기준 이용 가능` 또는 `현재 운영시간 외`로 표시한다. 반면 화면 시계는 30초마다 갱신된다. 서버 응답에 `generatedAt`은 있지만 `openNow`의 유효성을 끝내는 데 사용하지 않는다.

**근거:** `backend/src/adapters/tourApi.ts:48`, `:67`, `:143`; `backend/src/services/recommendations.ts:161`; `frontend/src/hooks/useRecommendations.ts:9`, `:35`; `frontend/src/components/SpotCard.tsx:114`, `:117`; `frontend/src/hooks/useClock.ts:5`.

**재현 절차(미실행):** 연중무휴·09:00–18:00처럼 현재 파서가 명시적으로 지원하는 자료를 사용한다 → 한국 시간 17:59에 응답을 만든다 → 검색 조건을 그대로 두고 18:01로 시계를 진행시키거나 브라우저를 그 시각에 다시 본다 → UI 시각이 바뀌어도 기존 `openNow`가 true인지 확인한다. 반대 방향으로 영업 시작 시각을 지나는 경우도 포함한다. 복잡한 영업시간 문법을 임의로 가정하지 않는다.

**영향:** 같은 화면 안에서 현재 시계와 운영 상태가 서로 다른 시각을 가리킬 수 있다. 상세 정보에 방문 전 확인을 안내하더라도, `현재`라는 판단은 시간이 지나면 효력을 잃는다. 오래된 운영 상태는 점수와 추천 보류 조건에도 남는다.

**최소 개선:** `openNow`에 계산 시각과 만료 시각을 명시하고, 신뢰할 수 있는 시간표의 다음 경계에서 갱신한다. 당장 경계 계산을 넣기 어렵다면 일정 시간이 지난 응답은 `조회 당시 운영시간 기준 · 다시 확인`으로 바꾸고 창 복귀 시 갱신한다. 최신 여부가 확보되기 전에는 현재 이용 가능으로 유지하지 않는다.

**완료 기준:** 지원하는 영업 시작·종료 시각을 넘겼을 때 카드와 추천 조건이 함께 갱신되거나 명시적으로 오래된 결과 상태가 된다. 응답이 오지 않아도 기존 true를 현재 사실처럼 계속 보여 주지 않는다.

## 적용 순서

전국 화장실의 성공/부분 실패 계약을 먼저 분리하고, 추천에 오류 상태를 반영한 다음, 시간 의존 값의 수명을 정의한다. 모두 기존 초록 지도·시설 종류·도움 전화 흐름을 유지하면서 데이터의 의미를 바로잡는 변경이다. 완료 판단은 점수 역전 합성 테스트, 보강 자료 장애 주입 테스트, 시간 경계 테스트의 세 가지로 한정한다. 실제 모바일 가독성·센서 반응·외부 통화 성공은 이번 코드 점검의 검증 범위에 포함하지 않는다.
