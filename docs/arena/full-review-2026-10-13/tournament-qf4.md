# 8강 QF4 · 전문가파 vs 실험파

심사 자료: `round1-expert.md`, `round1-experiment.md`, `browser-evidence.md`. 원저자 여부를 배제하고 공통 5기준을 각 10점으로 평가했다. 앱 변경과 추가 실행은 하지 않았다.

**전문가 → 실험 공격:** 비동기 마커 제거는 확인했지만 실제 포커스 이동은 실행하지 않았으므로, 모바일·보조기기 조작성 개선 효과를 확정하는 근거로는 아직 부족하다.

**실험 → 전문가 공격:** 확인된 배점으로 나누는 상대 점수 모델에서 정보 누락에 따른 점수 상승은 산술 오류가 아니며, 모든 누락에서 등급·순위를 올리지 말라는 규칙은 별도의 제품 정책 선택인데 수정 완료 조건처럼 제시했다.

| 공통 심사 기준 | 전문가 | 실험 | 판단 근거 |
|---|---:|---:|---|
| 급할 때 도움 발견성 | 7 | 8 | 전문가는 신뢰도 중심이고, 실험은 날씨 대기와 시설 이용 지연을 직접 연결한다. 양쪽 모두 전화 경로의 별도 접근 가능성을 침해했다고 주장하지 않는다. |
| 모바일 가독성·조작성 | 5 | 7 | 전문가는 현재 표시의 의미를 다루지만 조작 증거는 적다. 실험은 무반응 복구 버튼을 구체화했고 포커스는 검증 대기 조건으로 제한했다. |
| 데이터·위치 정직성 | 9 | 8 | 전문가는 보강 자료 누락과 시간 의존 판단의 상태 계약을 깊게 확인했다. 실험도 응답 미완료와 실제 시설 부재를 구분한다. |
| 오류·권한·빈 결과 복구 | 8 | 9 | 전문가의 부분 실패 상태 분리는 중요하다. 실험은 이미 10km인 빈 결과 버튼이라는 직접적 복구 실패와 비동기 완료 순서를 함께 다룬다. |
| 재현 근거·실행가능성 | 9 | 9 | 양쪽 모두 순수 실험과 미실행 통합 검증을 구분한다. 실제 API 성능·사용자 실패율을 만들지 않았고 코드 행과 최소 변경이 구체적이다. |
| **합계** | **38/50** | **41/50** | **실험파 승** |

승리 이유: 실험안은 사용자가 누르는 복구 버튼과 기다리는 조회의 동작을 작은 변경·통제된 응답으로 검증하게 해 실행 우선순위가 더 분명하다. 전문가는 데이터 의미의 분석이 강하지만, 상대 점수 정책의 재설계와 이미 코드로 확인된 오류 상태 누락을 같은 확정성으로 다루지 않도록 좁힐 필요가 있다. 격차는 3점이며, 실험의 포커스 문제를 실제 결함으로 실측했다고 인정한 점수는 아니다.

증거 해석: 전문가의 의료 정보 제거 후 **82→100점, 확인율90→70%, RECOMMENDED→PRIORITY**는 합성 입력으로 순수 함수에서 확인한 계산 결과다. 실제 병원/관광지의 안전성이 높아진 사례가 아니며, 데이터 가용성이 달라진 상대 지표의 성질을 보여 준다. 사용자가 긍정적 배지를 현재 이용 가능성으로 읽을 위험은 별도의 제품 문제다. 부모 브라우저에서 22시대 운영 미확인인 관광지에 `추천 가능/83점`이 앞선 관찰은 그 표현상의 우려를 뒷받침하지만, 합성 점수 역전의 실제 운영 재현은 아니다. 같은 브라우저 기록은 포커스 손실도 검증하지 않았다. 지도 모듈 실패가 도움 버튼까지 지운 재현은 별도 전체 점검의 중요한 증거이며 이 두 답의 미실행 조건에 실증 점수를 대신 주는 데 사용하지 않았다.

패자에게서 흡수할 요소는 **전국 화장실 보강 자료의 부분 실패 상태를 별도로 노출하는 계약** 딱 하나다. 점수 모델 변경과 시간 만료 정책은 이번 승자안에 추가하지 않는다.

## 흡수 후 수정 완성안

초록 지도와 전국 시설 구성을 유지하면서, 사용자가 하던 행동이 오류·대기·갱신 뒤에도 이어지는지 네 조건으로 점검하고 수정한다. 먼저 LIVE·전체 필터·10km의 빈 결과에서 `10km로 다시 찾기`가 현재 의존값을 바꾸지 않는 문제(`ExploreApp.tsx:480`, `useRecommendations.ts:35`)를 고쳐 이미 10km이면 실제 재조회 또는 위치 선택으로 이어지게 한다. 다음으로 시설과 날씨를 함께 기다리는 계약(`mapFacilities.ts:14`)을 분리해 날씨 응답 전에도 준비된 시설 목록과 연락 행동을 사용할 수 있게 한다. 여기에 패자안의 한 요소를 흡수하여 전국 화장실 보강 manifest·타일 실패가 정상 0건으로 보이지 않도록 자료 상태를 따로 반환하고, CCTV 등 정상 자료는 유지하면서 화장실에만 일부 자료 표시임을 알린다(`publicFacilities.ts:73`–`:93`). 마지막으로 경찰 핀 포커스 중 병원 자료 도착·resize를 브라우저에서 재현하여 포커스 손실 여부를 먼저 판정하고, 재현될 때 안정적인 ID 재사용 또는 해당 시설·군집으로의 제한적인 복원을 적용한다(`TourSafeMapPanel.tsx:113`–`:155`). 완료 증거는 10km 버튼의 실제 요청/화면 변화, 날씨 미완료 중 시설 사용 가능, 화장실 보강 장애와 정상 빈 결과의 구분, 비동기 갱신 중 포커스 보존·비탈취다. 현재 확인하지 않은 포커스 실패나 실서버 지연시간을 이미 발생한 결함처럼 보고하지 않는다.
