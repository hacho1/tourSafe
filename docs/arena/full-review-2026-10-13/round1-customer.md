# 고객시점파 — 처음 쓰는 사람의 전체 흐름 점검

2026-10-13. 초록색 커스텀 지도와 숫자 군집을 보존한다. 검토 질문은 “이 버튼을 누르면 무엇이 되나?”, “바로 가도 되나?”, “한 손으로 할 수 있나?”이다. 이전 도전자 보고서는 읽지 않았으며 이번 보고서는 아래 코드와 모바일 증거에서 새로 구성했다.

**핵심 판단:** 화면이 조용하고 정돈되어 있지만, 처음 쓰는 사람에게 필요한 행동의 뜻까지 조용해진 부분이 있다. 긴 설명을 추가하기보다 버튼 이름과 판단 정보를 실제 행동 옆에 배치하는 것이 우선이다.

직접 `view_image`로 확인한 증거: `docs/national-toilets-clusters-2026-10-13/mobile-jeju.jpg`. 390×844 캡처에는 제주 시청 기준점, 우측 지도 설정 아이콘과 내 위치, 하단 CCTV·경찰·의료·화장실·목록, 고정 도움 탭이 보인다. 숫자 군집은 유지 대상이다. 이번 에이전트는 실시간 브라우저·실기기 조작을 하지 않았다. 아래의 동작은 코드 확인, 화면 외형은 이 캡처 관찰, 사용자 오해·성공률은 추정으로 구별한다.

## 사실에 근거한 개선점 4건

### 1. ‘경찰/의료’ 버튼의 실제 뜻은 ‘찾기’가 아니라 ‘표시 끄기/켜기’다 — P2

**확인 사실:** 캡처의 버튼에는 시설 이름과 작은 체크만 보인다. 화면에 보이지 않는 그룹 이름만 `지도 시설 표시`다(`frontend/src/components/LivePlacesMap.tsx:150`). 각 버튼 클릭은 `toggleLayer`로 연결되고(`:151`), 그 함수는 해당 Boolean을 반전한다(`:68`–`:70`). 실제 시설 목록은 별도 `목록` 버튼(`:152`) → 종류 선택(`:162`)으로 진입한다.

**재현:** 경찰 표시가 켜진 상태에서 ‘경찰’을 누른다. 경찰 목록이 열리는 대신 경찰 표시가 사라진다. 버튼 기능 자체는 코드대로 정상이며, 이를 구현 버그라고 주장하지 않는다.

**고객 영향/추정:** 처음 온 사용자가 경찰에 가려는 의도로 눌렀을 때 예상과 반대 결과를 받을 수 있다. 이름만으로 동작을 학습하기 어렵다. 한 번 터치하고 사라지는 현상을 데이터가 없다는 뜻으로 받아들일 가능성도 있다.

**최소 수정:** 바 위에 짧은 가시적 제목 `지도에 표시`를 놓거나, 보조 텍스트로 `표시 중/숨김`을 드러낸다. `목록`은 `주변 목록`처럼 목적을 구체화한다. 접근성 이름도 상태에 맞춰 `경찰 표시 끄기/켜기`로 바꾼다. 표시 선택과 시설 찾기 동작을 같은 버튼 이름으로 암시하지 않도록 한다.

**완료 기준:** 처음 쓰는 5명에게 누르기 전에 기능을 설명하게 하고, 시설 버튼과 목록 버튼의 결과를 정확히 예상하는지 확인한다. 목표는 구현 통과보다 동작 예측 가능성이다.

### 2. 병원 지도 카드에서 ‘지금 갈 수 있나’ 판단 정보가 길찾기 뒤에 숨는다 — P2

**확인 사실:** 지도 선택 카드의 이름 아래에는 곧바로 `전화 문의/길찾기`가 나온다(`frontend/src/components/LivePlacesMap.tsx:138`–`:141`). 진료과, 오늘 요일의 등록시간, 접수 여부 전화 확인 문구는 `open`이 없는 `details`의 `주소·상세 정보` 안에 있다(`:142`–`:143`). 반면 별도 병원 화면은 `등록시간`과 `현재 접수 여부는 전화 확인이 필요해요`를 카드 본문에 보여준다(`frontend/src/components/HospitalFinder.tsx:203`–`:204`). 이 명확한 화면의 진입은 `주변 목록 → 병원·응급의료 → 병원 진료과·요일별 시간표`다(`LivePlacesMap.tsx:162`, `:165`).

**재현:** 병원 핀이나 의료 목록에서 병원을 선택 → 카드의 상세를 펼치지 않고 보이는 정보를 읽는다. 거리·이름·길찾기는 있지만 현재 진료·접수 여부에 대한 경계는 보이지 않는다. 실제로 병원이 닫혔다거나 앱이 현재 영업이라고 표시한다고 주장하지 않는다.

**고객 영향/추정:** 병원 핀의 존재와 길찾기 버튼을 ‘지금 도움받을 수 있다’는 확인으로 과대해석할 수 있다. 특히 바쁠 때 운영시간이 `주소·상세 정보`에 있을 것으로 예상하지 못할 수 있다.

**최소 수정:** 지도 카드 행동 버튼 바로 위에 `현재 접수는 전화 확인이 필요해요` 한 줄을 항상 보인다. 확인된 등록시간이 있으면 `오늘 등록 09:00–18:00`처럼 출처 성격을 붙여 같이 노출한다. 진료과·전체 시간표·자료 갱신 정보는 접힌 영역에 남긴다. 현재 영업 여부를 계산해서 단정할 필요는 없다.

**완료 기준:** 상세를 펼치지 않은 지도 병원 카드만 읽어도 현재 접수는 미확인임을 알 수 있고, 한 번 눌러 전화 문의로 이어진다.

### 3. 한 손으로 지도를 세 단계 확대하려면 설정을 세 번 다시 열어야 한다 — P2

**확인 사실:** 캡처의 기본 지도에 +/−는 없고 우측 상단 슬라이더 아이콘만 있다. 몰입형 지도에서는 확대/축소 버튼이 `지도 설정` 모달 안에 있으며(`frontend/src/components/TourSafeMapPanel.tsx:189`–`:197`), 한 번 누르면 `zoomIn/zoomOut` 직후 `closeSettings()`를 호출한다(`:196`–`:197`).

**재현:** 배경 지형을 살펴보려고 `설정 → 확대`를 누른다. 모달이 닫힌다. 같은 버튼으로 두 단계 더 확대하려면 `설정 → 확대`를 두 번 더 반복한다. 총 6번 터치다. 핀 군집 클릭에 따른 확대는 별도 경로이며, 두 손가락 확대도 존재하므로 확대 자체가 불가능하다는 뜻은 아니다.

**고객 영향/추정:** 짐이나 아이 손을 잡은 사용자가 한 손으로 크기만 조절할 때 불필요하게 화면을 전환한다. 설정 아이콘이 확대 기능을 담고 있다는 사실도 처음에는 발견하기 어렵다.

**최소 수정:** 지도 바깥 우측 여백에 44px 이상의 +/−를 상시 제공한다. 공간을 늘리기 어렵다면 설정 안에서 확대/축소 후 모달을 닫지 않는 최소 변경도 가능하지만 지도 가시성이 떨어지는지 확인해야 한다. 테마와 건물 표시만 설정에 두는 안이 이해하기 쉽다.

**완료 기준:** 한 손가락으로 원하는 배경 지역을 세 단계 확대·축소할 때 한 번씩 3회 동작하고, 설정을 다시 찾지 않는다. 초록 지도 스타일은 그대로 유지한다.

### 4. 같은 지도에서 단독 CCTV의 터치 크기만 36px로 작아진다 — P3

**확인 사실:** 일반 핀은 44×44px(`frontend/src/calm-map.css:48`), 단독 CCTV는 36×36px(`:50`), 숫자 군집은 44×44px(`:51`)로 정해져 있다. 실제 클릭 핸들러는 이 마커 button에 붙는다(`frontend/src/components/TourSafeMapPanel.tsx:119`, `:137`). 핀 이름은 기본 숨김이며 hover/focus/selected에서 나타난다(`frontend/src/reference-map.css:48`–`:49`). 캡처에서도 단독 카메라 표식이 숫자 군집보다 작게 보인다.

**재현:** 숫자 군집을 확대해 CCTV가 단독 핀으로 분리된 상태에서 선택한다. CSS상 선택할 버튼의 폭과 높이는 각각 8px씩 줄어든다. 이번 점검에서 실제 오터치율을 측정하지 않았고, 특정 접근성 표준 위반으로 판정하지 않는다.

**고객 영향/추정:** 확대하면 찾기는 쉬워지지만 손가락으로 누를 면적은 작아진다. 사용자가 군집에서 학습한 터치 감각과 달라질 수 있다.

**최소 수정:** CCTV 그림과 배경의 시각 크기는 36px로 유지해도 실제 button은 44px 이상으로 통일한다. 투명한 외곽 여백을 이용하되 인접 핀과 터치 영역이 겹치지 않는지 군집 간격과 함께 확인한다.

**완료 기준:** 단독 핀·숫자 군집 모두 같은 최소 터치 크기를 제공하며, 화면 크기 360px에서도 주변 핀을 대신 선택하는 일이 없는지 실기기에서 확인한다.

## 정성 개선안

- **문구는 ‘자료 유형’보다 다음 행동을 설명한다.** `의료`는 넓은 용어이므로 목록에서는 `병원·응급의료`를 유지하고, 지도에서는 짧은 보조 안내로 ‘진료과·시간표는 목록에서’를 연결한다. `LIVE · 공공데이터`는 최신 연결 상태를 뜻하지만 실시간 접수 가능으로 오해할 여지가 있어 `공공 등록정보`와 조회 시각의 조합을 검토한다. 기존 전화 확인 문구는 잘 작성되어 있으므로 주요 카드에서도 같은 언어를 일관되게 사용한다.
- **처음 한 번의 성공을 짧게 검증한다.** “근처 경찰 연락처 찾기”, “진료과를 확인하고 병원에 전화하기”, “화장실 개방시간 확인하기”, “여행지 상세로 들어가 저장하고 저장 표시 확인하기”를 설명 없이 수행하게 한다. 버튼별 클릭 여부가 아니라 첫 클릭의 의도 일치, 연락/길찾기 전 오해, 원래 목록으로 돌아가는 시간을 기록한다. 도움 화면의 112·119 전화 선택을 방해하는 추가 온보딩은 넣지 않는다.

실행 우선순위는 **병원 행동 전 확인 문구 → 시설 토글/목록의 뜻 명확화 → 한 손 확대/축소 → CCTV 터치 크기**다. 지도 교체나 색상 전면 개편 없이 적용할 수 있다. 화면 크기와 사용자 이해에 관한 결론은 위 과업 검증 전까지 추정으로 남긴다.
