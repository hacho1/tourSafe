TourSafe — 1단계 아레나 검토
검토일: 2026-10-11
범위: 앱을 보고 있을 때 흔들기 또는 버튼으로 주변 장소 확인

방법
arena 스킬에 따라 8개 전략안을 제출받았다. 동시 실행 한도에 맞춰 3개 하위 에이전트를 사용하고, 완료된 에이전트에 새 전략을 명시해 재배정했다. 서로의 답은 보여주지 않았다. 주 에이전트가 실제 브라우저 화면과 원본 코드를 확인하고 대진별 상호 비판, 채점, 장점 흡수를 수행했다. 점수는 내부 설계 판단이며 사용자 조사 결과나 제품 성능 수치가 아니다.

공통 평가 기준 (각 5점, 합계 25점)
목적 명확성 / 조작·접근성 / 정보 신뢰성 / 화면 가독성 / 현재 구현 가능성

확인된 문제
1. '내 주변 안전정보'의 가장 큰 숫자는 현재 위치 점수가 아니라 기준점에서 직선 694m 떨어진 가상 공원의 97점이다.
2. '정보 확인율 100%'는 정보의 정확성·최신성·안전 확률을 뜻하지 않는데 강한 긍정 표시로 보인다.
3. 가상 데이터와 점수 범위 설명이 결과창 아래에 있어 첫 화면에서 놓치기 쉽다.
4. 지도와 민트 경로의 시각적 정체성은 명료하지만 주변 조회와 흔들기 설정은 긴 경로 선택 영역 아래에 있다.
5. 실제 자료를 제공하지 않는 DEMO 상태에서도 현재 위치 권한을 요청하는 버튼이 있다.

제출된 8개 완성안 요약
1 정석파: 주변 장소 확인 버튼과 바텀시트. 예시/기준점/결과 장소/직선거리/방문정보 순. 숫자 링 제거, 닫기와 초점 복귀.
2 역발상파: 안전점수와 흔들기를 대표로 내세우는 가정을 재검토. 확인 가능한 사실과 '장소 자세히 보기'를 중심에 둠.
3 숫자파: 출처, 자료 기준 시각, 조회 시각을 분리. 확인되지 않은 항목은 점수로 환산하지 않음. 지도 기준점 선택을 제안하나 현재 개념도에는 해당 기능 없음.
4 스토리파: 밤에 성수에 도착한 여행자가 멈추고, 한 장소를 이해하고, 지도로 복귀하는 장면. 장소와 지도 간 연속성 강조.
5 고객 시점파: '어떤 곳인가요 / 지금 방문할 수 있나요 / 주변 의료시설은 어디인가요'에 답하는 밝은 카드. 숫자는 접힌 계산 설명으로 이동. 권한 없이 첫 경험 가능.
6 극단 간결파: 한 장소와 한 행동에 집중. 숫자와 배점 제거. 예시 상태의 주 버튼을 현재 위치 조회로 두는 제안은 현재 자료 상태와 맞지 않음.
7 전문가파: 기준점과 결과 장소를 구분하고, 취소/응답 역전/가상 자료 혼입을 차단. 정보의 범위를 데이터 계약에 맞춤.
8 실험파: 지도 아래 접고 펼치는 방문 전 확인표. 재조회와 단순 열기를 구분. 현 단계에는 추가 상태 관리와 검증 범위가 큼.

8강 1경기: 정석파 vs 역발상파
정석파 관점의 공격: 대표 점수를 없애는 논리만으로 사용자의 구체적 읽기 순서가 충분하지 않다.
역발상파 관점의 공격: 익숙한 패턴만 적용하면 장소 점수를 지역 안전으로 읽는 근본 문제를 놓칠 수 있다.
점수: 정석파 4/4/5/4/4 = 21, 역발상파 5/4/5/4/4 = 22.
승자 역발상파. 흡수: 정석파의 기준점→결과 장소→거리 순서와 닫기/초점 복귀.

8강 2경기: 숫자파 vs 스토리파
숫자파 관점의 공격: 밤길 이야기의 정서가 현재 운영 여부까지 확인했다는 인상을 주지 않도록 해야 한다.
스토리파 관점의 공격: 출처와 시각을 모두 앞세우면 방문 판단이 서류 읽기가 되며 새 지도 선택 기능도 필요하다.
점수: 숫자파 4/4/5/4/3 = 20, 스토리파 5/4/4/5/4 = 22.
승자 스토리파. 흡수: 자료 기준 시각과 서버 조회 시각을 분리하고 누락을 명시.

8강 3경기: 고객 시점파 vs 극단 간결파
고객 시점파 관점의 공격: DEMO에서 현재 위치 버튼을 주 행동으로 두면 제공할 정보 없이 권한부터 요구한다.
극단 간결파 관점의 공격: 질문형 설명이 길어지면 장소명과 행동이 첫 화면 아래로 밀린다.
점수: 고객 시점파 5/5/5/5/4 = 24, 극단 간결파 4/4/3/5/5 = 21.
승자 고객 시점파. 흡수: 첫 화면의 핵심 정보를 세 묶음 이내로 제한하고 세부 근거는 접기.

8강 4경기: 전문가파 vs 실험파
전문가파 관점의 공격: 접힌 상태의 재사용은 조회 기준이나 자료가 바뀌었을 때 오래된 결과를 섞을 수 있다.
실험파 관점의 공격: 정확한 상태 처리만으로 지도와 결과가 분리되는 사용자 경험을 해결하지 못한다.
점수: 전문가파 4/5/5/4/5 = 23, 실험파 4/4/4/5/3 = 20.
승자 전문가파. 흡수: 기존 지도를 유지하면서 필요한 근거만 펼치는 정보 구조.

4강 1경기: 역발상파 vs 스토리파
역발상파 관점의 공격: 밤 시간 장면만 강조하면 실제 야간 자료가 없는 앱의 범위를 넘기 쉽다.
스토리파 관점의 공격: 점수 비판에 치우치면 사용자가 무엇을 얻는지 긍정적으로 설명하기 어렵다.
점수: 역발상파 5/5/5/4/4 = 23, 스토리파 5/4/5/4/4 = 22.
승자 역발상파. 흡수: '한 장소를 이해하고 상세를 확인한 뒤 지도에 돌아온다'는 완결된 행동 흐름.

4강 2경기: 고객 시점파 vs 전문가파
고객 시점파 관점의 공격: 오류·권한 설명이 주 화면을 차지하면 불안한 사용자의 첫 질문에 답하지 못한다.
전문가파 관점의 공격: 쉬운 문구라도 이전 응답이 새 위치에 붙으면 화면이 잘못된 사실을 전달한다.
점수: 고객 시점파 5/5/5/5/4 = 24, 전문가파 4/5/5/4/5 = 23.
승자 고객 시점파. 흡수: 조회 기준 검증, 늦은 응답 무시, 취소, DEMO·LIVE 혼합 차단.

결승: 역발상파 vs 고객 시점파
역발상파 관점의 공격: 점수 계산을 남겨두면 여전히 안전 보장으로 해석될 수 있다.
고객 시점파 관점의 공격: 점수를 완전히 삭제하면 사용자가 요청한 비교 아이디어를 검증할 기회도 없앤다.
점수: 역발상파 5/5/5/4/4 = 23, 고객 시점파 5/5/5/5/4 = 24.
우승 고객 시점파. 흡수: 모든 진입점의 표현을 '주변 장소'로 통일하고, 계산 설명에 장소 방문 조건만 평가한다는 범위를 명시한다.

우승안 — 구현 기준
홈: 기존 짙은 초록·민트 지도 유지. 지도 위쪽에 '주변 장소 확인' 카드와 주 버튼. 흔들기는 같은 카드의 선택 설정, 기본 꺼짐.
결과: 첫 화면에 예시 여부, 조회 기준·반경, 장소명·종류·직선거리. 운영시간과 해당 장소 주변의 의료시설을 먼저 표시. 시설 거리는 내 위치 기준으로 오해하지 않게 표시.
근거: 확인하지 못한 값과 없는 것으로 확인된 값을 구분. 출처와 자료 시각 표시. 기존 점수와 가중 확인율은 접힌 '방문 조건 계산 보기'에 배점 근거와 한계를 함께 표시.
행동: 기존 장소 상세로 연결, 닫으면 지도 복귀. DEMO에서 위치 권한 요청 금지. LIVE에서만 사용자가 직접 위치 조회를 선택.
상태: 로딩, 취소, 실패·미설정, 빈 결과, 기준 좌표 불일치, 가상/실제 자료 혼입을 구분. 실패를 예시 결과로 덮지 않음.

왜 이겼나
1 사용자가 첫 화면에서 장소와 조회 기준을 구분하고 다음 행동을 선택할 수 있다.
2 기존 디자인과 점수 비교 아이디어를 유지하면서 과도한 안전 판단 인상을 줄인다.
3 현재 API와 상세 화면을 재사용하므로 실제 자료·새 지도 SDK 없이 첫 단계를 검증할 수 있다.

결승 대안
역발상파: 점수를 전부 제거하고 출처가 있는 사실만 보여주기. 사용자 테스트에서 접힌 계산도 지역 안전점수로 계속 오인된다면 이 방향으로 전환한다.

검증 대상
좁은 모바일/데스크톱 표시, 버튼→조회→상세→복귀, 키보드·초점, 예시 표시, DEMO GPS 비활성, 조회 상태 판단 단위 테스트, 기존 테스트와 빌드. 실제 휴대폰 센서, 실제 GPS 및 공공기관 실응답은 별도 실기기/키 연동 검증이 필요하다.

구현·검증 결과
우승안의 상단 진입 카드, 선택형 흔들기, 장소 중심 결과, 접힌 계산·출처, 기존 상세 연결을 D:/tourSafe에 구현했다.
기술 검토에서 추가로 확인한 쿨다운 초기화와 숨김 중 센서 미지원 오판 문제도 수정했다.
npm test: 28/28 통과. npm run build: 성공.

브라우저에서 네트워크 단절→오류→복원→재시도 통과. 2.5초 지연 조건에서 조회 취소 뒤 상태 유지 확인. 테스트 설정은 복원했다.
수집된 브라우저 JavaScript 경고·오류 없음. 별도 검토 직원의 정적 검토에서도 출하를 막는 확정 결함은 발견하지 못했다. 이는 실서비스 안전성 인증이 아니다.
실제 휴대폰 동작 센서·권한과 LIVE GPS 연속 요청·공공기관 실응답은 미검증이다.
