# 모바일 지도·흔들기 기능 아레나

2026-10-13 · 독립 도전자8명, 상호 반박을 거친7경기. 같은 근거와5가지 기준을 주고 동시 실행 한도 안에서 묶음으로 진행했다. 이후 상대 답을 공개하고 공격·자기약점·흡수요소를 받았다. 주 에이전트가 정성 심사했다. 실제 이용자 실험이나 제품효과 수치가 아니다. 이번 작업은 검토이며 앱 코드를 바꾸지 않았다.

## 🏆 우승 답 — 전문가파

**평소 지도는 단순하게, 흔들면 연락할 곳을 고르는 도움 화면을 연다. 주변 시설의 수·거리는 평소 탐색에, 긴급 연락은 도움 화면에 둔다.**

현재 지도는 색상을 바꾸기보다 정보 우선순위를 바꾸는 것이 먼저다. 초록색 도로·공원·지도 표현은 유지하면서 기본 지도에서 큰 도움 카드, 필터 가로줄, 날씨, 건물·테마·모두보기 도구를 접는다.

### 모바일 첫 화면

- 상단: 조회 위치·검색을 한 줄로, 지도 설정은 표시 설정 메뉴로 모은다.
- 중앙: 넓게 보이는 기존 초록 지도. ‘내 위치’로 돌아가는 조작은 이름을 포함해 제공한다.
- 지도 하단: ‘주변 시설’ 한 진입점. 작고 찾기 어려운 아이콘만 두지 않고 충분한 터치 영역을 제공한다.
- 하단 메뉴: 기존 도움 찾기 탭을 ‘도움’으로 강조하고 지도·여행·저장 화면에서도 같은 위치로 유지한다. 별도 큰 도움 버튼·상단 SOS를 중복하지 않는다. 도움 화면이 열린 동안에는 탭이 모달 위에 남아 경쟁하지 않도록 한다.
- 주변 시설을 열면 병원·경찰시설·관광안내·화장실·CCTV 중 목적을 선택하고, 선택한 종류와 소수 후보만 표시한다. 많은 종류의 핀을 첫 화면부터 함께 켜지 않는다. 화장실은 현재 좌표가 없는 주소 자료라는 제약을 그대로 유지한다.
- 주요 조작부48px 안팎과 본문16px는 조작성 개선을 위한 설계 목표다. WCAG 충족 판정이나 실기기 검증 결과가 아니다.

### 흔들었을 때

기존 하단 도움 탭을 눌렀을 때와 **똑같은 도움 화면**을 연다. 새로운 전화번호 디렉터리를 길게 만들지 않는다.

1. 먼저 ‘위협·범죄 ·112’와 ‘화재·구급 ·119’. 명시적으로 눌렀을 때 전화 앱으로 연결하며, 화면 자체에서 통화 성공이나 신고 접수를 표시하지 않는다.
2. 그 아래 ‘여행 안내·통역 ·1330’을 긴급 연락보다 낮은 강조로 표시한다. 기관 용도와 번호를 함께 쓴다.
3. ‘내 위치 확인·복사’는 선택 기능이다. 위치 권한이나 시설 조회가 전화 선택을 막지 않는다. 실제 위치를 확인한 시각·정확도를 유지하고 수동 조회 장소를 신고 위치에 자동 채우지 않는다.
4. 주소 수정·건물명 직접입력과 큰 문장 보여주기는 필요할 때 펼치는 보조 기능이다. 문장 카드는 실험파에서 흡수한 제안으로, 첫 구현의 필수 기능으로 늘리기보다 후속 시안에서 유용성을 확인한다.
5. 흔들기는 직접 켜는 보조 입력이다. 잘못 열려도 화면만 열리고 발신·신고·녹화·위치전송은 하지 않는다. 닫으면 원래 화면과 초점으로 돌아오며, 오감지 뒤 끄기에도 접근할 수 있다. 센서 미지원·권한 거절 시 실제 도움 버튼 이름으로 안내한다.

기존 SOS의 번호·위치 확인·직접입력·복사 기능을 재사용하는 방향이다. 현재 웹의 흔들기를 화면이 꺼지거나 다른 앱을 보는 중에도 쓸 수 있다고 설명하지 않는다. [W3C 명세](https://www.w3.org/TR/orientation-event/)와 [MDN 권한 안내](https://developer.mozilla.org/en-US/docs/Web/API/DeviceMotionEvent/requestPermission_static)를 확인했다. 실제 센서와 전화 앱 동작은 휴대폰별로 검증해야 한다.

### 사용자가 제안한 개수와m 거리의 자리

아이디어 자체는 유지하되, 흔들었을 때 처음 보이는 정보로 삼지 않는다. ‘주변 시설’에서 짧게 읽고 행동으로 이어지게 한다.

- 경찰시설: ‘검색된 가까운 후보’ + 시설명 + ‘직선 ○m’ + 전화번호 제공 여부 + 길찾기. 현재 API는 가까운3곳으로 자르므로 ‘반경 안 총3곳’이라고 쓰지 않는다. 경찰서·파출소·지구대·치안센터를 모두 경찰서라고 부르지 않는다.
- CCTV: 예를 들어 ‘반경500m 등록 설치지점 ○곳’으로 표현할 수 있다. **500m는 제안이며 아직 구현된 집계가 아니다.** 축약된 지도핀 대신 원본 좌표 자료를 반경별로 집계하는 추가 작업이 필요하다. 지점수와 카메라 대수는 구분하고 등록자료 기준일을 표시한다.
- CCTV 개수·직선거리는 안전점수나 안전한 이동 경로, 현재 작동 여부가 아니다. CCTV 자체를 도움을 받을 수 있는 목적지로 추천하지 않는다.
- 성공한 빈 자료는 ‘해당 자료에서0곳’, 실패·미제공은 ‘확인 불가’로 구분한다. ‘등록0곳’도 실제로 시설이 없다는 뜻으로 확대하지 않는다.

연락처 근거: [경찰청112](https://112.go.kr/), [소방청119종합상황실](https://www.nfa.go.kr/nfa/introduce/organizationidfo/situation/), [한국관광공사1330](https://english.visitkorea.or.kr/svc/contents/contentsView.do?vcontsId=140632).1330의24시간 운영이나 모든 통화의 무료 여부는 이 검토에서 주장하지 않는다.1330은 여행 안내·통역 등 서비스이며 긴급출동과 같은 역할이 아니다.

## 왜 이겼나

1. 지도와 긴급 도움의 정보 순서를 나눠 모바일 첫 화면에서 여러 행동이 경쟁하는 문제를 직접 줄인다.
2. 흔들기 실패에도 같은 도움 버튼을 사용할 수 있고, 위치 없이 연락하며 오감지에서 복귀하는 흐름이 구체적이다.
3. 현재 조회 장소·실제 위치, 후보수·전체수, CCTV 설치자료·안전 보장을 구분한다.

## 아깝게 진 답 — 정석파

준우승은 지도와 도움을 단계적으로 나누는 정석파다. 최종 반론을 거치며 우승안과 거의 같은 구조로 수렴했다. 정석파 역시 기존 하단 도움 탭을 강조하고 별도 큰 버튼을 없애며, 전화 선택→위치 확인 순서를 제안했다. 시설 수와 거리는 주변 시설 화면으로 옮겼다.

결승은 동점이었다. 전문가파가 후보수 상한·현재 위치 실패 복구·보조 동작 노출·오감지 뒤 끄기를 더 구체적으로 적어 동점 규칙으로 채택했다. 큰 사용자효과 차이가 입증됐다는 의미는 아니다.

방향이 가장 달랐던 안은 숫자파다. 주변 경찰시설 거리와 CCTV 집계는 평소 주변 파악에는 쓸모가 있을 수 있으나, 위급한 행동의 첫 정보로 채택하지 않았다. ‘도움 선택부터 띄우고 지도를 두 번째로’라는 역발상안은 현재 지도 탭을 열어 둘러보려는 사용자에게 단계를 추가해 탈락했다.

## 다음 구현과 확인 순서 제안

1. 모바일 기본 지도에서 겹치는 도구·카드를 접고 도움 진입점을 하나로 정리한다.
2. 기존 SOS를 간결한 도움 화면으로 정리한 뒤 버튼과 흔들기를 같은 화면에 연결한다. 폰을 흔들지 못해도 똑같이 사용할 수 있어야 한다.
3. 주변 시설에서 직선거리·전화·길찾기를 정리한다. 반경별 CCTV 집계는 그 이후에 추가한다.
4. 처음 보는 사람에게 위협 상황의 연락처 찾기, 주변 병원 찾기, 다른 도시를 조회 중일 때 실제 위치 구분을 맡겨 관찰한다. 번호를 누르는 부분은 모의 링크로 시험한다. 일반 탐색과 급한 도움 둘 다 덜 헤매는지, 버튼만 쓸 때보다 흔들기가 편한지는 별개로 측정한다. 도움 번호가 익숙한 사용자의 기본 전화 앱과도 비교한다.

작업량이나 화면이 단순해진 것만으로 실제 효용을 확정하지 않는다. 현재 화면에서도 연락할 수 있으므로 다음 변경은 처음 보는 사람이 덜 헤매는지 확인하는 시안으로 시작하는 것이 적절하다.
