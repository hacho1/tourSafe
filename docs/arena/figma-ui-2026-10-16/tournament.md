# TourSafe 모바일 UI 아레나 심판 기록

2026-10-16. 01~08 제출안 모두 확인. 이 문서는 답안 심사와 구현 범위만 기록하며 앱 코드를 수정하지 않는다. 심사자는 앞서 03·06 작성에 참여했으므로 저자 선호가 아니라 아래 동일 기준과 구체적인 차이로 판정한다.

## 근거와 판정 규칙

기준은 첫 화면 이해도 / 한 손 조작 / 지도 가시성 / 도움 찾는 단계 수 / 기존 기능 유지, 각 5점이다. 점수는 설계안에 대한 심판 평가이며 사용자 테스트 결과나 예상 개선율이 아니다. 동점이면 구현 동작이 더 구체적인 안을 고른다. 후속 경기는 앞 경기에서 수정된 안을 평가한다.

저장 캡처 두 장과 brief 지정 코드를 근거로 한다. 라이브 브라우저 검증과 사용자 테스트는 하지 못했다. 03의 지도 캡처 파일은 실제 390×843px로 확인했다. 지도 프레임 약 370×692px는 저장 이미지 경계의 근사치이고 면적비는 약 77.9%다. 조작부에 가려지지 않은 지도 면적을 뜻하지 않는다. CSS의 헤더 60px·핀 44px·레이어 버튼 최소 54px도 확인된다. 그 밖의 크기·탭 수 목표는 제안으로 명시되어 있다. 허위 사용자 성과·사례·인용 또는 근거 없는 실측 수치는 발견하지 못했으므로 즉시 탈락자는 없다.

‘도움 1회’는 연락처가 보일 때까지, ‘전화 2회’는 지도에서 도움을 열고 전화 앱을 여는 링크를 누를 때까지다. 통화 연결이나 신고 완료를 뜻하지 않는다. 이 경로는 전원이 유지하므로 도움 점수는 동일하다.

수정안 03-A: 중앙 지도 공간과 네 토글을 유지하고 마지막 종류의 목록을 바로 연다. 목록 종류·스크롤·선택 시설·지도 중심을 상태로 보존한다. 도움을 열고 닫아도 이전 카드로 돌아가며, 카드에서 목록으로 돌아갈 때 이전 결과 위치를 복원한다. 고정 220px 카드 목표는 긴 이름이나 글자 확대 시 내용 접근을 막는 상한으로 사용하지 않는다.

수정안 06-A: 위치 검색에는 ‘조회 기준’, 시설판의 네 버튼에는 체크와 ‘지도 표시’라는 그룹 이름, 별도 버튼에는 ‘목록’을 부여한다. 그룹 이름은 작은 라벨 또는 접근성 이름으로 처리해 독립 설명 패널을 만들지 않는다. 목록 상단은 현재 종류를 항상 표시한다. 기본·목록·선택 상태는 한 영역에서 전환하고 기존 의료 필터와 주소 목록을 유지한다.

우승: **06 극단 간결파**. 흡수할 한 요소는 03-B의 **마지막 시설 종류로 바로 진입**이다.

최종 수정안 06-C: 검색과 브랜드를 한 상단 영역으로, 네 레이어 토글과 목록을 한 하단 시설판으로 모은다. 목록은 마지막 종류의 결과를 즉시 열며 첫 진입은 ‘경찰시설’이라고 명확히 표시한다. 종류 선택기를 열면 여섯 분류를 모두 고를 수 있다. 목록에서 시설을 고르면 같은 영역이 카드로 바뀌어 토글과 상세 카드가 수직으로 쌓이지 않는다. 연락처는 고정 도움 메뉴에서 한 번에 드러난다. 지도와 모든 기존 기능은 유지하고 상태·포커스 복귀를 명시한다.

왜 이겼나: 처음 읽어야 하는 독립 영역이 줄고, 목록 진입의 중간 선택 화면을 줄일 수 있다. 선택 카드와 시설판의 동시 노출을 없애 지도 위 중복 면적을 직접 줄인다. 도움 경로와 기존 데이터 기능을 보존하면서 접근성 복귀 규칙을 갖춘다. 실제로 더 빠르거나 편안하다는 사용자 성과는 아직 확인되지 않았다.

아깝게 진 답: 03-B는 측정 기준을 중심으로 현 구조를 조금씩 바꾸는 대안이다. 헤더와 기존 영역 구분을 남겨 두고 싶을 때 적용하기 쉽지만 이번 목표인 조작부 통합에서는 06-C가 더 구체적이다.

## 최종 1차 구현 범위

### 1. 기본 지도

- 모바일 지도 화면의 독립 60px 브랜드 헤더를 위치 검색 영역에 통합한다. 브랜드명과 조회 기준은 남기되 같은 정보가 별도 헤더·제목에 반복되지 않게 한다. 데스크톱과 여행지·저장 화면은 범위 밖이다.
- 상단에는 위치 검색과 설정을 하나의 시각적 묶음으로 둔다. ‘내 위치로 조회’는 시설판 바로 위 오른쪽에 둔다. 지도 이동 뒤 ‘이 위치에서 다시 찾기’는 기존 조건에서만 표시하며 조회 위치와 지도 중심의 차이를 보존한다.
- 하단 시설판은 CCTV·경찰·의료·화장실 토글과 목록의 한 줄이다. 토글 네 개는 기본 지도에서 즉시 보인다. 각 토글의 서로 다른 큰 색 채움은 공통 중립 바탕과 체크/테두리 상태로 바꾼다. 지도 핀의 종류별 색과 아이콘, aria-pressed는 보존한다. 색만으로 켜짐을 전달하지 않는다.
- 앱 하단 네 메뉴와 도움의 고정 위치를 유지한다. 지도와 컨트롤의 배치는 앱 메뉴 및 안전영역을 포함해 계산한다.

### 2. 시설판·목록·카드 전환

- map / list / selected의 표시 상태를 명확히 한다. 기존 조회 로직과 MapCanvas를 교체하지 않고 LivePlacesMap의 표시 상태와 렌더링만 정리한다.
- 목록은 마지막 카테고리의 결과로 바로 진입한다. 기록이 없으면 ‘경찰시설’로 시작하고 제목에 이를 표시한다. 다른 종류는 현재 종류 선택기에서 여섯 개 모두 고를 수 있다. ‘경찰’이 사용자에게 가장 적절한 시설이라고 추천하는 표현은 쓰지 않는다.
- 기본 시설판과 선택 카드를 같은 하단 슬롯에서 상호 배타적으로 보여준다. 선택 상태에서 토글을 조작하려면 카드를 닫아 기본 시설판으로 돌아간다. 토글 기능을 삭제하거나 상태를 초기화하지 않는다. 이 한 번의 복귀가 지도를 더 넓게 보여주는 대신 생기는 명시적인 절충이다.
- 카드 기본 정보는 이름·종류·직선거리·전화 문의·길찾기 또는 방문 정보다. 긴 이름은 두 줄 이후 상세에서 전체를 읽을 수 있게 하고, 주소·등록정보·출처·자료 한계는 펼침 영역에 보존한다. 전화번호가 없으면 전화 동작을 만들지 않는다.
- 목록에서 연 카드는 ‘목록으로’, 지도에서 연 카드는 닫기로 원래 맥락에 복귀한다. 카테고리·목록 스크롤·선택 시설·지도 중심을 보존한다.

### 3. 도움과 기능 보존

- 도움 메뉴 → 연락처 노출 1회, 연락처 링크 → 전화 앱 열기까지 총 2회라는 현재 경로를 유지한다. 112·119·1330의 용도를 표시하며 위치 권한 확인이 연락처를 가리지 않는다.
- 위치 확인·전달, 흔들기 옵션, 신고 안내, 이용·연락처 안내를 유지한다. 도움을 닫으면 기존 지도/목록/선택 상태와 포커스로 돌아간다.
- 의료 종류 필터와 진료과·요일 시간표, 관광지 방문 정보, 화장실 주소 검색·좌표 미확인 목록, 추가 결과, CCTV 설치자료 설명, 오류·부분자료·빈 결과의 구분, 새로 조회, 설정 안의 날씨와 지도 안내를 빠뜨리지 않는다.
- 실시간 안전점수·운영 여부 추정·자동 신고·새로운 번호 핀·새 지도 엔진·API 변경은 1차 구현에 포함하지 않는다.

### 4. 크기와 검수 목표

- 320·390·430px에서 시설판 버튼은 최소 48×48px를 목표로 한다. 좌우 12px와 5개 버튼, 패딩·간격을 합친 실제 너비를 계산하고 오버플로를 확인한다. 토글 이름은 숨기지 않는다.
- 기본 본문 16px를 목표로 하고 크기 확대 시 카드·시트의 내용을 잘라 맞추지 않는다. 짧은 화면에서는 제목과 닫기를 남긴 채 시트 내부를 스크롤한다. 작은 화면에 고정 150px/220px 카드 상한을 강제하지 않는다.
- 기본 상태: 독립 브랜드 헤더가 없고 네 토글+목록은 한 줄인지, 선택 상태: 카드 아래에 토글이 중복으로 쌓이지 않는지, 토글별 큰 색 블록이 공통 바탕으로 줄었는지를 캡처로 확인한다.
- 목록 진입 후 현재 종류의 시설을 선택할 때는 목록 버튼→시설의 2회 경로를 확인한다. 다른 종류로 변경하는 경우에는 선택기 조작이 추가되므로 모든 시설이 무조건 2회라고 주장하지 않는다.
- 320×568, 390×844, 430×932에서 지도/목록/카드/도움 캡처를 비교하고 긴 시설명·200% 글자 확대·위치 거부·자료 오류·전화번호 없음 상태를 확인한다. 자동 초점 이동, 모달 안의 키보드 이동, 닫기 복귀도 검수한다.
- 현재 브라우저 접근 차단으로 이 검수는 아직 실행되지 않았다. Figma 시안과 코드 검토 결과를 실제 브라우저 검수 완료로 표시하지 않는다.
